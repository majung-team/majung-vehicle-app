# 주행 중 조작 제한과 도착 처리

## 조작 제한

공식 [Pleos 주행 규제 가이드](https://document.pleos.ai/docs/pleos-only/vehicle-app-developer-guide/driving-restriction-development-guide)에 따라 CarUxRestrictionsManager를 구독한다. 초기 상태, Car 서비스 해제, 조회 실패는 조작 금지다. 시스템이 DO 불필요·추가 제한 없음으로 확인한 때만 이 개발 화면의 버튼을 허용한다.

장소 선택·등록·생성·참여 승인·수동 도착·완료·취소와 권한 요청을 같은 기준으로 막는다. 제한 전환 시 열린 대화상자를 닫고, 비동기 장소 목록과 대화상자의 실행 직전에도 재검사한다. 화면 제한으로 이미 승인된 백그라운드 공유 서비스를 끄지는 않는다. 앱에 DO 승인 표시를 추가하지 않았으며, 주행 중 화면 사용 심사를 통과했다는 뜻은 아니다.

Pleos 2.1.0 에뮬레이터에서는 android.car API가 모듈로 제공된다. 일반 shared library 이름을 필수로 선언하면 설치가 실패하므로 compile 시 useLibrary로 참조하고 별도 필수 uses-library 선언을 넣지 않는다. SDK 바이너리는 저장소에 포함하지 않는다.

## SDK 도착

경유지·최종 목적지 도착 이벤트를 받더라도 바로 서버 상태를 바꾸지 않는다. 아래 조건이 모두 맞아야 한다.

- 현재 서버 픽업의 확정 장소가 최신 검증 경로에 하나만 존재
- 이벤트의 경유지 순서와 장소 이름이 해당 지점과 일치
- SDK 위치·해당 지점 ETA가 기존 10초 유효 범위 이내
- 해당 지점 ETA가 60초 이내이고 위치가 약속 장소 반경 100m 안에 있음
- 픽업이 ACTIVE이며 재실행 후 공유 재개 확인을 마친 상태

이름·인덱스만으로 장소를 추측하지 않는다. 경로가 무효화됐거나 다른 지점·중복 좌표·위치 미수신이면 자동 도착을 보내지 않고 수동 확인을 남긴다. 서버 도착 요청이 실패해도 ARRIVED로 먼저 표시하지 않는다. 30초 안에 최대 3회만 시도하고, 다른 픽업·종료·재개 확인 대기로 바뀌면 중단한다. 서버 도착 처리는 반복 호출에도 같은 상태를 유지한다.

반경과 ETA는 보수적인 초기 조건이다. 실차에서 정확도를 검증한 값은 아니며, 픽업 완료·공유 종료는 탑승 확인과 별도다.

## 검증과 제한

- 단위 시험: 미확인·허용·제한·연결 해제, 잘못된 도착 순서·이름·좌표 중복·이전 경로·먼 위치·긴 ETA 거절.
- 실제 에뮬레이터: Car UX 상태 조회와 서비스 해제 후 차단 확인.
- Android 화면 시험: 제한 상태 전환을 시험 입력으로 주어 열린 대화상자 종료·버튼 차단·허용 후 복구 확인.
- Android HTTP 시험: 다른 장소 도착 무시, 첫 도착 요청 503 시 ACTIVE 유지, 제한된 재시도 후 ARRIVED, 이후 중복 전송 없음.
- 실제 SDK의 이동·경유지 도착 콜백은 아직 재현하지 못했다. 경유지 변경 콜백이 도착 콜백보다 먼저 와 경로를 무효화하면 보수적으로 자동 도착을 생략할 수 있다. 이를 실차 자동 도착 완료로 표시하지 않는다.
- 공식 주행 제한 ON/OFF 명령의 hmg_car_service가 현재 에뮬레이터에 없어 해당 실전환 시험은 건너뛴다. 상태 조회·시험 입력 검증과 실제 주행 전환 시험을 구분한다.
