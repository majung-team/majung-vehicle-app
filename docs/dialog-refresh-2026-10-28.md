
# 차량 팝업 버튼 및 연결 상태 새로고침 개선

**수정일:** 2026년 10월 28일  
**차량 앱 버전:** `0.2.10-preview`

차량 앱의 검색 팝업에서 버튼 상단이 잘리는 문제와 운전자 연결 상태를 새로고침할 때 발생하는 불필요한 화면 갱신을 개선한 기록이다.

공식 Pleos 에뮬레이터에서 UI 배치를 확인하고, 지연 응답을 적용한 시험 서버로 새로고침 중 상태 유지와 중복 요청 방지를 검증했다.

---

## 1. 검색 팝업 버튼 잘림

### 문제 현상

검색 팝업에서 하단 버튼의 윗부분이 일부 잘려 보이는 현상이 발생했다.

에뮬레이터에서 버튼과 부모 영역의 실제 좌표를 확인한 결과, 버튼의 상단 위치가 부모 영역보다 **4px 위에 배치**되어 있었다.

### 원인 및 수정

기본 `ButtonBarLayout`의 기준선 정렬이 버튼 배치에 영향을 주는 것을 확인했다.

이에 따라 다음 항목을 수정했다.

- `ButtonBarLayout`의 기준선 정렬 비활성화
- 버튼 영역의 높이 조정
- 버튼 내부 간격 정리
- 버튼이 부모 영역 안에 배치되는지 확인

동일한 스타일을 사용하는 QR·확인·취소 팝업에도 수정 사항을 적용했다.

### 수정 후 화면

![검색 팝업 버튼](media/dialog-footer-2026-10-28.png)

공식 Pleos 에뮬레이터에서 수집한 검색 팝업 화면이다.

좌우 버튼이 부모 영역 안에 배치되는지 확인했다.

## 2. 운전자 연결 상태 새로고침

### 기존 문제

운전자 계정 연결 상태를 다시 조회하는 과정에서 불필요한 UI 갱신이 발생할 수 있었다.

새로고침은 서버의 최신 연결 상태를 확인하기 위한 기능이므로, 조회 중에도 기존 화면 정보와 사용자의 탐색 상태를 유지할 필요가 있었다.

### 개선 내용

**기존 계정 정보 유지**

새로고침 요청 중 기존 운전자 정보를 즉시 비우지 않는다.

서버 응답을 확인한 후 필요한 계정 정보만 갱신한다.

**진행 상태 표시**

요청이 진행되는 동안 버튼 문구를 다음과 같이 변경한다.

`새로운 정보 확인 중…`

버튼은 중복 실행을 방지하지만, 비활성화 색상으로 변경하지 않는다.

**중복 조회 방지**

새로고침 버튼을 연속해서 눌러도 같은 조회 요청을 여러 번 실행하지 않는다.

**부분 화면 갱신**

계정 상태 조회 콜백은 계정 영역만 갱신한다.

다음 동작은 수행하지 않는다.

- 메뉴 이동 애니메이션 재시작
- 내비게이션 영역 전체 갱신
- 픽업 영역 전체 갱신
- 스크롤 위치 초기화

### 새로고침 흐름

```text
새로고침 선택
       ↓
기존 계정 정보 유지
       ↓
'새로운 정보 확인 중…' 표시
       ↓
서버 연결 상태 조회
       ↓
조회 중 추가 클릭 차단
       ↓
응답 결과 확인
       ↓
계정 영역만 갱신
       ↓
기존 버튼 문구 복원
```

새로고침은 기존 연결 상태를 조회하는 기능이다. 새로운 연결 요청이나 계정 승인을 생성하지 않는다.

## 3. 테스트 환경

| 항목 | 환경 |
| --- | --- |
| 시험일 | 2026년 10월 28일 |
| 차량 앱 | `0.2.10-preview` |
| 실행 환경 | 별도 Pleos 에뮬레이터 |
| UI 대상 | 검색·확인 팝업, 계정 새로고침 |
| 서버 | 시험용 HTTP 서버 |

실제 운영 서버의 응답 시간을 측정한 결과가 아니라, UI 상태 유지 여부를 확인하기 위해 지연을 적용한 시험이다.

## 4. 검증 결과

| 검증 항목 | 결과 |
| --- | --- |
| 검색 팝업의 좌우 버튼 배치 | 부모 영역 안에 표시 확인 |
| 500ms 응답 지연 중 기존 정보 유지 | 확인 |
| 새로고침 중 버튼 위치 유지 | 확인 |
| 새로고침 중 스크롤 위치 유지 | 확인 |
| 연속 클릭 시 서버 조회 | 한 번만 실행 |
| 조회 성공 후 버튼 문구 복원 | 확인 |
| 차량 계정·픽업 복구·주행 요약 시험 | 11건 실행 |
| 별도 실제 P → D → P 시험 | 조건부 건너뜀 |
| 단위 테스트 | 통과 |
| Android Lint | 통과 |

### 회귀 테스트

차량 계정, 픽업 복구 및 주행 요약과 관련된 시험 11건을 실행했다.

실제 P → D → P 전환을 요구하는 별도 시험 1건은 실행 조건이 충족되지 않아 건너뛰었다.

건너뛴 시험을 통과한 것으로 기록하지 않는다.

해당 주행 제한 전환의 별도 검증 기록은 [주행 중 픽업 요약 화면](driving-summary.md)에서 확인할 수 있다.

## 5. 검증 범위 및 한계

이번 변경에서는 다음 항목을 확인했다.

- 팝업 버튼의 실제 배치 좌표
- 지연 응답 중 기존 계정 정보 유지
- 중복 새로고침 요청 차단
- 계정 영역의 부분 갱신
- 기존 화면 위치 및 상태 유지

다만 시험은 공식 Pleos 에뮬레이터와 지연 응답을 적용한 시험 서버를 기준으로 수행했다.

따라서 다음 항목까지 검증한 결과는 아니다.

- 실제 운영 환경에서 발생한 모든 지연의 원인
- 실제 차량 디스플레이별 버튼 배치
- 실차 주행 제한 상태의 화면 동작
- 실제 휴대전화와의 연동 성능
- 다양한 네트워크 지연 상황에서의 응답 시간

이번 수정은 **확인된 UI 배치 문제와 새로고침 동작을 개선한 결과**이며, 사용자가 경험한 모든 일시적인 지연의 원인을 규명한 것은 아니다.
