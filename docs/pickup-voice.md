
# 픽업 음성 안내

마중 차량 앱은 탑승자의 준비 완료와 픽업 장소 도착 상태를 음성으로 안내할 수 있다.

Pleos TextToSpeech SDK를 사용하며, 운전자가 직접 활성화한 경우에만 안내한다.

음성 안내는 기본적으로 꺼져 있고, 설정한 사용 여부는 차량에 저장한다.

---

## 1. 음성 안내 기능

### 안내 메시지

| 상황 | 음성 안내 |
| --- | --- |
| 탑승자 준비 완료 | "탑승자가 준비를 마쳤어요." |
| 픽업 장소 도착 | "약속 장소에 도착했어요. 안전하게 정차한 뒤 탑승을 확인해주세요." |

개인정보 노출을 줄이기 위해 다음 정보는 음성으로 읽지 않는다.

- 탑승자 이름
- 마중 ID
- 픽업 장소 이름

### 사용 설정

차량 설정에서 **음성 안내 켜기**를 선택하면 기능이 활성화된다.

음성 안내를 끄면 이후 안내는 재생하지 않으며, 진행 중인 재생도 중단한다.

설정 변경에는 차량 시스템의 주행 제한 정책을 적용한다.

주행 제한 상태에서는 음성 안내 설정을 조작할 수 없다.

## 2. SDK 구성

| 항목 | 구성 |
| --- | --- |
| 음성 SDK | Pleos TextToSpeech 3.3.1 |
| 실행 모드 | `ON_DEVICE` |
| 클라우드 인증 키 | 불필요 |
| 안내 정책 | `PickupVoicePolicy` |
| 재생 및 오디오 처리 | `PickupVoiceGuide` |

`ON_DEVICE` 모드를 사용하여 차량 환경에서 음성 안내를 처리한다.

별도의 클라우드 TTS 인증 키를 요구하지 않는다.

음성 엔진의 초기화, 재생 및 중지 결과를 확인하며 각 작업에는 제한 시간을 적용한다.

음성 기능 오류가 발생하더라도 픽업 상태 처리나 위치 공유를 막지 않도록 구성했다.

---

## 3. 음성 안내 발생 조건

음성 안내는 진행 중인 픽업에서 새롭게 확인한 상태 변화에 따라 실행한다.

### 준비 완료 안내

탑승자의 준비 상태가 준비 완료로 변경되고 차량 앱에서 해당 변화를 확인한 경우 안내한다.

### 도착 안내

현재 픽업의 도착 상태가 새롭게 확인되면 안내한다.

차량 도착과 실제 탑승 완료는 별개이며, 도착 안내가 재생됐다고 해서 픽업이 자동으로 종료되지는 않는다.

### 안내하지 않는 상황

- 음성 안내가 비활성화된 경우
- 동일한 상태가 반복 조회된 경우
- 같은 픽업에서 이미 안내한 상태인 경우
- 앱 복구 이전에 발생한 과거 상태 변경
- 차량 연결이 끊긴 동안 발생한 변경
- 사용자 공유 재개 확인 전의 상태 변경

안내 대상이 아닌 상태는 뒤늦게 재생하지 않는다.

---

## 4. 중복 및 오래된 안내 방지

`PickupVoicePolicy`는 현재 프로세스에서 새롭게 관찰한 상태 변화 중 음성 안내가 필요한 이벤트를 판단한다.

### 중복 안내 제한

동일한 픽업에서는 이미 안내한 준비 완료나 도착 상태를 반복해서 읽지 않는다.

다음 상황에서도 이전 안내가 다시 재생되지 않도록 처리한다.

- 같은 상태의 주기적 서버 조회
- 준비 중과 준비 완료의 반복 전환
- 앱 화면 재진입
- SDK 및 서버 재연결
- 음성 안내 설정을 다시 켠 경우

### 복구 후 처리

앱이 재실행되면 기존 픽업 상태를 확인하지만, 이전에 발생한 준비 완료나 도착 이벤트를 자동으로 음성 안내하지 않는다.

사용자가 픽업 공유 재개를 확인하기 전에는 안내를 시작하지 않는다.

연결이 끊긴 동안 발생한 과거 상태 변경도 나중에 몰아서 재생하지 않는다.

이 정책은 오래된 정보가 현재 발생한 상황처럼 전달되는 것을 방지하기 위한 것이다.

---

## 5. 백그라운드 동작

`PickupVoiceGuide`는 앱에 속한 픽업 상태 관찰자로 동작한다.

기존 `PickupSharingService`가 화면 밖에서도 픽업 상태를 조회하는 동안 상태 변화를 확인할 수 있다.

화면이 내려간 상태에서도 새로운 안내 대상이 확인되면 음성 재생을 시도할 수 있다.

다만 다음 상황에서는 자동 재생을 수행하지 않는다.

- 앱 프로세스가 강제 종료된 경우
- 픽업 복구 후 사용자 재개 확인 전
- 이미 종료된 픽업
- 위치 공유 권한이 없는 상태

차량 시동 OFF/ON 이후 자동 안내까지 검증된 구조는 아니다.

---

## 6. 오디오 포커스 및 오류 처리

음성 안내는 차량의 다른 오디오 사용 상황을 고려한다.

### 오디오 포커스

- 음성 재생 전 오디오 포커스 요청
- 포커스를 얻지 못하면 음성 안내 생략
- 포커스를 잃으면 진행 중인 재생 중단
- 통화 등 다른 오디오 사용 상황에서는 포커스 상태에 따라 처리

음성 재생이 불가능하더라도 차량 화면의 상태 안내는 유지한다.

### 재생 종료 조건

다음 상황에서는 음성 안내를 중단한다.

- 픽업 공유 종료
- 차량 통신 연결 중단
- 사용자가 음성 안내를 끈 경우
- 오디오 포커스를 잃은 경우

### SDK 오류 처리

SDK 초기화·재생·중지 작업에는 제한 시간을 둔다.

음성 엔진의 오류나 응답 지연이 픽업 요청, 준비 상태 처리, 탑승 완료 기능을 차단하지 않도록 구성했다.

음성 안내는 픽업 기능을 보조하며 필수 진행 조건으로 사용하지 않는다.

## 7. 테스트 및 검증 결과

### 차량 JVM 테스트

**39개 통과**

주요 검증 항목:

- 준비 완료 상태 변화
- 도착 상태 변화
- 같은 픽업의 중복 안내 방지
- 준비 상태 반복 전환
- 복구 후 과거 상태 안내 억제
- 재연결 후 오래된 이벤트 억제
- 음성 설정 변경
- 종료 후 안내 방지

### Android 계측 테스트

**4개 통과**

가상 서버를 사용하여 다음 항목을 확인했다.

- 준비 및 도착 상태 수신
- HTTP 503 응답
- 연결 복구
- 픽업 종료
- 음성 설정 저장

### 실제 Pleos SDK 확인

공식 Pleos 에뮬레이터에서 `ON_DEVICE` 모드로 다음 동작을 확인했다.

- TTS SDK 초기화
- 재생 시작 콜백
- 재생 완료 콜백

## 8. 아직 검증하지 않은 범위

SDK 콜백 확인과 실제 차량에서 소리가 정상적으로 들리는지는 별개의 검증이다.

해당 에뮬레이터 시험은 호스트 오디오 출력을 끈 상태에서 진행했다.

따라서 다음 항목은 확인되지 않았다.

- 실제 스피커에서의 음성 출력
- 안내 음량 및 음질
- 전화 통화 중 TTS 동작
- 내비게이션 음성과의 실제 우선순위
- 장시간 실행 중 음성 출력 안정성
- 실차 오디오 환경에서의 동작

이번 시험은 SDK 초기화 및 재생 관련 콜백이 정상적으로 발생했음을 확인한 결과다.

실제 사용자가 음성을 들을 수 있었음을 검증한 결과는 아니다.
