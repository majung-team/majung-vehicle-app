# 전송 결과와 실제 공유 상태

차량 시계가 서버보다 약 112초 늦은 시험에서 서버는 STALE을 반환했지만 앱은 전송 성공을 표시했다. HTTP 성공만으로 탑승자에게 보이는 상태를 판단한 것이 원인이었다.

- PUT 응답이 FRESH이고 validForMillis가 양수일 때만 최신 정보를 공유 중이라고 표시한다.
- STALE은 공유하지 않는 상태로 안내하고 차량 날짜·시간과 SDK 갱신을 확인하도록 한다.
- 미래 sourceTime 거절은 자동 날짜·시간 설정을 안내한다. 역순 요청은 별도 안내한다.
- WAITING은 자료 대기 상태다. DELETE 응답이 WAITING일 때만 이전 정보 삭제를 확인한다.
- 알 수 없는 응답·연결 실패는 성공으로 표시하지 않는다. 서비스 실행 알림도 전송 성공을 의미하지 않도록 문구를 바꿨다.

sourceTime은 SDK 콜백을 받은 원래 시각을 보낸다. 만료를 피하려고 전송 순간의 시각으로 바꾸지 않는다. 서버의 기존 30초 만료와 만료 시 위치·ETA를 숨기는 처리는 유지한다.

## 검증

- 단위 시험: STALE, WAITING, 알 수 없는 응답, FRESH의 남은 유효 시간, 미래·역순 오류 구분.
- Android HTTP 연동 시험: 실제 PickupApiClient와 PickupController에 STALE → FUTURE_SOURCE_TIME → FRESH → DELETE/WAITING 응답을 순서대로 전달한다. 112초 이전 sourceTime이 그대로 전송되는지도 확인한다.
- 위 연동 시험은 응답을 통제한 시험이다. 실제 차량 시계 설정·실차 주행을 재현한 결과는 아니다.
