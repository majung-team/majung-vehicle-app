# 받은 요청으로 마중 시작하기

## 운전자 사용 순서

1. **받은 요청**에서 사람과 만날 장소를 확인한다.
2. 새 요청은 **수락하고 마중 준비**, 대기 중인 요청은 **마중 가기**를 누른다. 이미 다른 픽업이 진행 중이면 대기에만 추가한다.
3. 앱이 내비 경로를 확인한다. 그 장소가 이미 경로에 있으면 그대로 사용한다. 없으면 기존 최종 목적지와 경유지를 유지하면서 새 경유지를 한 번 추가한다.
4. 검증이 끝나면 **마중 시작 · 위치 공유**를 누른다. 처음에는 위치 권한을 허용해야 할 수 있다.
5. 도착 후 탑승을 확인하면 위치 공유가 끝난다. **다음 대기자 확인**에서 다음 사람을 고른다.

경유지가 이미 두 곳이면 내비에서 경로를 정리해야 한다. 준비 취소는 마중 요청을 취소하거나 이미 추가한 경유지를 삭제하지 않는다. 자동으로 내비를 되돌리면 운전자가 바꾼 경로를 덮어쓸 수 있어 그대로 둔다.

## 기다림과 오류

내비 초기 연결에 성공·실패 응답이 모두 없으면 12초 뒤 연결 오류를 표시하고 재연결할 수 있게 한다. 연결 세대 번호를 바꿔 늦게 도착한 이전 응답을 사용하지 않는다. 에뮬레이터 재시작으로 복구된 사례의 SDK 내부 원인까지 확인한 것은 아니다.

요청의 전체 경로 준비는 최대 60초 기다린다. 연결·경로 확인 실패, 취소·만료, 장소 변경, 운전자 변경은 시작을 차단한다. 새로고침이 경유지 추가나 픽업 시작 요청을 반복하지 않는다. 시작 응답을 받지 못하면 자동 재전송하지 않고 결과 확인 안내를 표시한다. 동일 요청 시작은 서버의 기존 중복 방지 처리를 사용한다.

서버 요청 목록을 마지막으로 확인한 지 15초가 넘으면 최신 목록을 기다린다. 다른 활성 픽업은 차량 앱의 로컬 상태뿐 아니라 서버에서 읽은 요청 목록에서도 확인한다. 앱이 재실행되면 진행 중인 픽업은 기존 암호화 세션 복구를 사용한다. 경로 준비만 하던 작업은 자동 재개하지 않고 요청을 다시 선택한다.

연결이 끊겼을 때 이전 ETA를 계속 표시하지 않는다. 앱을 재실행해 복구한 픽업은 운전자가 계속하기를 확인한 뒤 위치 공유를 재개한다. 완료·취소·만료 후에는 기존 종료 처리로 공유와 접근을 차단한다.

## 화면 동작

연결된 사람이 없는 초대 창에서는 **사람 찾기 / QR로 초대**로 바로 이동한다. 검색·확인 창은 폭을 제한하고 글씨·터치 영역을 키웠다. 메뉴 전환은 0.18초 동안 본문이 짧게 들어오고 창은 0.18초 동안 나타난다. 위치·ETA 갱신에는 효과를 넣지 않는다. 시스템에서 애니메이션을 끄면 효과를 생략하고, 주행 제한 시 진행 중인 효과도 중단한다.

## 코드와 확인 범위

- `RequestPickupFlow`: 경로 준비·확인·시작 상태와 시간 제한. 요청이나 경로를 디스크에 별도로 저장하지 않는다.
- `VehicleApplication`: 실제 계정·내비·픽업 컨트롤러 연결.
- `RequestPickupSection`: 경로 준비·오류·시작 확인 화면.
- 단위 시험: 중복 경유지·시작 방지, 경로 변경, 오래된 목록, 취소·만료, 다른 운전자·활성 픽업, 다음 대기자, 응답 유실.
- 에뮬레이터 검사: 초기 연결 응답 누락, 계정·초대·첫 연결, 저장 세션 복구·통신 실패·종료 정보 삭제, 주행 요약.
- 실제 SDK 경로 수신과 요청 준비 확인을 별도로 검사한다. 이 검사의 시작 API는 시험용이며 실제 사람의 픽업을 만들지 않는다.
- 실제 휴대전화와 실차에서의 전체 흐름은 별도 확인 대상이다.


![검색 결과 창](media/people-dialog-2026-10-27.png)

검색 결과 캡처는 에뮬레이터 앱 창의 시험용 계정이다. 실제 회원 정보가 아니다.

실제 SDK 시험에서 경로 수신과 요청 준비·명시적 시작 확인까지 성공했다. 이어진 `cancelRoute` 시험은 안내가 유지돼 실패했다. 설정용 연결과 현재 조회 연결에서 같은 현상이 관찰돼 [별도 이슈 #56](https://github.com/majung-team/majung-vehicle-app/issues/56)로 남겼고, 취소 검사를 삭제하지 않았다. 픽업 종료는 내비 안내를 취소하지 않고 서버 공유를 끝내므로 이 항목과 구분한다.

## 여백 기준

설명과 진행 표시, 진행 표시와 카드 사이를 나눠 놓았다. 확인 창은 본문 아래 16dp, 버튼 위 12dp를 확보하고 버튼 사이에는 8dp를 둔다. 목록의 안쪽 여백은 픽셀이 아닌 dp로 계산한다. QR 창의 이미지 영역은 320dp로 제한해 본문과 하단 조작이 불필요하게 멀어지지 않게 했다.
